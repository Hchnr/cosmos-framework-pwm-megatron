# TP/PP 项目问题与处理记录

更新时间：2026-11-25（UTC）。本文用于对外汇报，滚动记录影响交付的主要问题、处理结果和后续计划；详细实现与实验记录见 [TP/PP 实现说明](../megatron_tp_pp.md) 和 [项目计划](v0.0.1.tp_pp.md)。后续出现新的重要问题或状态变化时，继续在本文更新。

## 当前结论

Megatron TP/PP 训练路径已完成阶段性实现，并通过部分小规模运行和恢复检查。**完整模型正确性尚未通过，四卡 TP4 的整机吞吐也尚未打平 FSDP4**；当前结果不能作为最终交付或生产性能验收。

上述梯度相对 L2 差异以裁剪前的全模型梯度计算，等于梯度差的 L2 范数除以原生基线梯度的 L2 范数；它不是逐元素误差的最大值或平均值。对照每步复用相同的两份裁剪后预处理输入，并校验输入指纹；第三步包含前两步的参数漂移。新一轮诊断以 master 为受控初值，四卡可训练参数及优化器初始状态逐项一致，三步观察重现上述差异，运行后文件身份校验通过。第三步最大的单个参数张量占梯度差平方约 2.63%，前五个合计约 9.73%；差异分布在多个参数中。参数、主要输出和梯度为 FP32，但部分输入在预处理时已有低精度量化，不能将此视为完整生产数据验收。

进一步将第二、三步开始前的参数和优化器状态分别重置为原生对应状态后，整体梯度相对误差降至约 0.0045% 和 0.0056%，仍有参数分片未通过逐项检查。这提示先前状态差异是后续误差放大的重要因素；同状态下的残余差异和连续训练一致性仍未解决，重放仅用于定位，不能视为连续训练通过。

Q 投影候选在相同裁剪输入的连续三步探索中，将梯度相对误差降至约 0.0052%、0.0357% 和 4.26%；第三步仍全部梯度分片未通过，候选未作为修复启用。本次对大文件进行了身份与抽样检查，未重新全量哈希，结果仅用于定位。

在相同裁剪输入和初始状态下，同时替换 Q 与第 0 层视频 K/V 前向投影后，三次更新的整体梯度相对误差为 **0.0040%、0.1006%、14.65%**。首步逐参数梯度及输出均通过；四卡记录均无算子回退，但第三步误差超过原实现，候选未启用。此次仍采用大文件身份和抽样校验。下一轮将对照固定的原生参数和 Adam 状态，区分单步算子误差与累积更新造成的放大。

Q-only 同状态对照起初在第三步前触发主机内存保护，逐步释放已使用的参考文件缓存后，重跑完成三步及完整后校验。其三步整体梯度相对误差约为 **0.00518%、0.00278%、0.01669%**。使用相同起点和随机状态的 Q 加 K/V 配对重放也完成了完整后校验，误差为 **0.00396%、0.00219%、0.00415%**。两组固定状态的最后两步均远低于各自连续更新的误差，仍有分片超限。对照确认了状态差异会放大后续误差，具体算子和连续训练修复仍待验证。

新一轮 Q-only 连续三步对照完成完整后校验，复现了约 0.0052%、0.0357% 和 4.26% 的梯度相对误差。只替换第 11 层 action q_norm 权重梯度的候选，在首次反向传播被上游梯度的形状、精度与布局检查拦下，未完成更新。进程已清理，未继续对该次失败运行做全量后校验。

复测确认四卡均收到同一种非连续梯度布局。支持该布局后，候选完成三次更新和完整后校验，第三步整体梯度相对误差仍为约 4.26%，四卡各有 811 个梯度分片未通过。与先前 Q-only 结果数值接近，两轮诊断采用不同的源码清单。该局部改动未能解决误差放大。

针对误差累积，已在单卡上用存档的裁剪前梯度和真实范数重算原生裁剪，并用原生 FusedAdam 更新。四个参数的 15 个采样分片共 60 项权重及优化器状态逐位一致。这为后续分开验证 TP 裁剪和 Adam 提供了原生参照，完整 TP 轨迹仍待验证。

真实四卡 FP32 首步对同一份 TP 梯度比较两种范数计算顺序，差约 **1.3×10⁻⁵**，而 TP 与原生训练的范数差约 **0.0086**。用原 TP 范数重算裁剪后，96 条采样记录均逐位吻合。该结果将首步范数差的主要来源定位在裁剪前。后续将检查上游投影与 Adam 对连续误差的影响。

为定位同状态下仍超限的梯度，已完成第 32 层视频 Q 投影的原生和四卡 TP 采集。两侧使用相同更新前权重和两个微批。单卡 GPU 重放逐位复现了原生及四个 TP 分片各自的输出、逐微批权重梯度和累计梯度，前后校验通过。

在首个微批固定原生全宽投影时，仅换入 TP 的上游梯度使权重梯度相对差约为 **0.0101%**，仅换入 TP 的前向输入约为 **0.00065%**。CPU FP64 分解也指向上游梯度是该投影差异的主要来源。

两侧的 Q 分支采集及六个边界的配对校验均已完成。两个微批在注意力返回的 Q 梯度处均已有差异。首个微批跨过 Q 归一化反向后，梯度差的 L2 范数从 **1.72×10⁻⁷** 增至 **7.11×10⁻⁶**。用实际权重做 FP64 局部重算，复现了这组差异，实测差与重算差之间的残差范数约 **4.66×10⁻⁹**。该处误差主要随输入的上游梯度进入，后续检查注意力反向，完整模型连续训练差异仍未解决。

原生和四卡 TP 的注意力操作数均已完成采集与后校验，两个微批的 mask 逐位一致。FP64 中单独替换首个微批的 Q 或输出梯度，分别产生 **1.32×10⁻⁷** 和 **8.90×10⁻⁸** 的 Q 梯度差，单独替换 K 或 V 的影响较小。第二个微批同样以 Q 和输出梯度为主。CPU FP32 重放未能逐位复现原 CUDA 结果，后续改用同一 CUDA 后端重放。

同一 CUDA 数学后端已逐位复现两侧全部 10 组原始输出和 Q 梯度，并完成 50 次操作数替换和后校验。将 TP 的四个操作数换入原生形状后，两个微批的 Q 梯度差分别只剩原先的约 **0.9%** 和 **3.2%**。这将该层的排查重点放到注意力的 Q 输入和输出梯度来源；完整模型连续训练差异仍待解决。

独立的 checkpoint 问题已修复。全新 driver 曾遗漏恢复 Adam 动量，现按 checkpoint 中的分片构造加载状态，并检查 DCP 索引完整性。CPU 回归和四卡 FP32 小模型的三种拓扑均通过恢复与续跑。缺少动量且无法验证完整性的旧分布式 checkpoint 会被拒绝；完整模型和 BF16 的恢复仍待验收。

## 性能对比口径

四卡对比采用 **TP=4、PP=1 与 FSDP=4**，两边每个 rank、每个 microstep 使用相同 batch；不强求每次更新的全局样本数相同。双方使用 BF16，TP4 采用实验性的 VAE 分片候选。三次 microstep 分别处理 9、11、13 个样本，预热 2 次更新后统计 5 次更新：

| 方案                | 平均更新耗时 |      四卡整机吞吐 |
| ------------------- | -----------: | ----------------: |
| TP4（VAE 分片候选） |  约 14.46 秒 | 约 2.28 samples/s |
| FSDP4               |  约 34.21 秒 | 约 3.86 samples/s |

该轮 TP4 候选约为 FSDP4 吞吐的 **59%**。两者每次更新处理的全局样本数分别为 33 和 132，因此以整机 samples/s 为准。本次包括输入准备、VAE、训练与优化器，不包括媒体解码和 checkpoint 写入。固定 fixture 在不同 rank 间复用，样本数按处理次数计，资源监控与历史 checkpoint 校验仍有限制。更早的 TP2/PP2 与 FSDP 单步数据采用不同的批次和累积设置。

11 月 24 日按同样的 microstep batch 加入逐槽计时。TP4 完成 2 次预热和 5 次计时更新，FSDP4 在收到暂停指令前完成 2 次预热和 4 次计时更新。取双方共同的 4 次更新，每步以四卡中最慢 rank 的计时为准，TP4 为 14.57 秒、2.27 samples/s，FSDP4 为 34.34 秒、3.84 samples/s，吞吐比例仍约为 59%。这是中断前的诊断数据，正式对比仍以完整计时窗口为准。TP4 的数据准备在主机侧约占 7 秒/步，这段计时包含 GPU 工作和等待，需用端到端复测确认可节省的时间。

为减少 VAE 分片的数据传输，已准备 uint8 候选并通过四进程 CPU 对照。真实四卡试验修正了 NCCL 批量收发完成句柄和带 slots 的数据类校验。修正后，FP32 分片与 uint8 分片在同一组 9、11、13 样本的输入上逐字节通过了 eager VAE latent 和训练准备结果检查。uint8 的原始视频跨卡传输量降低 **75%**，例如 11 样本时从约 1.81 GiB 降至 0.45 GiB。完整模型、AOT 与整机吞吐仍待复测。

同源码的 36 层 TP4 eager 诊断中，关闭 uint8 后五个计时步平均约 **15.54 秒/步**。开启后仅首个预热槽使用 uint8，其余 20 槽均因数据准备所在 rank 的显存准入不足而回退。五个计时步全部使用回退路径，本次 FSDP4 未启动。短诊断测得首个回退时该 rank 空闲显存 **6.22 GiB**，低于 **25.30 GiB** 的预算；分配器保留约 **29 GiB** 尚未分配给张量。

单槽复验中，四卡同步清理未使用的显存缓存后，数据准备 rank 的空闲显存升至 **34.95 GiB**，按原预算重新准入通过。该槽的 latent、准备数据和 owner 随机状态与原生参考精确一致。各卡清理耗时约 **0.56–0.59 秒**；是否每槽都需要清理、重新分配的成本以及端到端收益，需用完整计时验证。

11 月 25 日完成同源码三组四卡对照。每组 2 步预热、5 步计时，每个 rank 的 microstep batch 依次为 9、11、13。输入与实际张量形状校验通过，所有进程均正常退出。

| 方案                      | 平均更新耗时 |    四卡整机吞吐 |
| ------------------------- | -----------: | --------------: |
| TP4，uint8 关闭           |     15.57 秒 | 2.120 samples/s |
| TP4，uint8 开启及缓存重试 |     15.33 秒 | 2.153 samples/s |
| FSDP4                     |     37.19 秒 | 3.549 samples/s |
