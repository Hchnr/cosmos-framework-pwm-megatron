# TP/PP 项目问题与处理记录

更新时间：2026-11-23（UTC）。本文用于对外汇报，滚动记录影响交付的主要问题、处理结果和后续计划；详细实现与实验记录见 [TP/PP 实现说明](../megatron_tp_pp.md) 和 [项目计划](v0.0.1.tp_pp.md)。后续出现新的重要问题或状态变化时，继续在本文更新。

## 当前结论

Megatron TP/PP 训练路径已完成阶段性实现，并通过部分小规模运行和恢复检查。**完整模型正确性尚未通过，四卡 TP4 的整机吞吐也尚未打平 FSDP4**；当前结果不能作为最终交付或生产性能验收。

## 性能对比口径

四卡对比采用 **TP=4、PP=1 与 FSDP=4**，两边每个 rank、每个 microstep 使用相同 batch；不强求每次更新的全局样本数相同。双方使用 BF16，TP4 采用实验性的 VAE 分片候选。三次 microstep 分别处理 9、11、13 个样本，预热 2 次更新后统计 5 次更新：

| 方案                | 平均更新耗时 |      四卡整机吞吐 |
| ------------------- | -----------: | ----------------: |
| TP4（VAE 分片候选） |  约 14.46 秒 | 约 2.28 samples/s |
| FSDP4               |  约 34.21 秒 | 约 3.86 samples/s |

TP4 候选当前约为 FSDP4 吞吐的 **59%**，尚未通过完整模型正确性验收。两者每次更新处理的全局样本数分别为 33 和 132，因此应比较整机 samples/s，而非直接比较秒/步。本次包括输入准备、VAE、训练与优化器，不包括媒体解码和 checkpoint 写入；固定 fixture 在不同 rank 间复用，样本数按处理次数而非独立样本计，资源监控与历史 checkpoint 校验仍有限制，结果为暂定值。更早的 TP2/PP2 与 FSDP 单步数据因批次和累积设置不同，不能直接比较。

## 后续重点

1. 完成完整模型 FP32 多步对照，定位并修复差异；随后验证 BF16、数据连续性和 checkpoint 恢复。
2. 在相同 microstep batch 和明确的资源、计时口径下，继续优化输入准备、计算与通信，复测四卡整机吞吐，目标为打平 FSDP4。
3. 完成 576 槽容量、完整续训及生产编译配置验收；所有新候选先验证数值和资源，再报告性能。
