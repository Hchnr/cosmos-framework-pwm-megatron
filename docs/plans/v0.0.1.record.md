# TP/PP 项目问题与处理记录

更新时间：2026-11-23（UTC）。本文用于对外汇报，滚动记录影响交付的主要问题、处理结果和后续计划；详细实现与实验记录见 [TP/PP 实现说明](../megatron_tp_pp.md) 和 [项目计划](v0.0.1.tp_pp.md)。后续出现新的重要问题或状态变化时，继续在本文更新。

## 当前结论

Megatron TP/PP 训练路径已完成阶段性实现，并通过部分小规模运行和恢复检查。**完整模型正确性尚未通过，四卡 TP4 的整机吞吐也尚未打平 FSDP4**；当前结果不能作为最终交付或生产性能验收。

上述梯度相对 L2 差异以裁剪前的全模型梯度计算，等于梯度差的 L2 范数除以原生基线梯度的 L2 范数；它不是逐元素误差的最大值或平均值。对照每步复用相同的两份裁剪后预处理输入，并校验输入指纹；第三步包含前两步的参数漂移。新一轮诊断以 master 为受控初值，四卡可训练参数及优化器初始状态逐项一致，三步观察重现上述差异，运行后文件身份校验通过。第三步最大的单个参数张量占梯度差平方约 2.63%，前五个合计约 9.73%；差异分布在多个参数中。参数、主要输出和梯度为 FP32，但部分输入在预处理时已有低精度量化，不能将此视为完整生产数据验收。

进一步将第二、三步开始前的参数和优化器状态分别重置为原生对应状态后，整体梯度相对误差降至约 0.0045% 和 0.0056%，仍有参数分片未通过逐项检查。这提示先前状态差异是后续误差放大的重要因素；同状态下的残余差异和连续训练一致性仍未解决，重放仅用于定位，不能视为连续训练通过。

Q 投影候选在相同裁剪输入的连续三步探索中，将梯度相对误差降至约 0.0052%、0.0357% 和 4.26%；第三步仍全部梯度分片未通过，候选未作为修复启用。本次对大文件进行了身份与抽样检查，未重新全量哈希，结果仅用于定位。

在相同裁剪输入和初始状态下，同时替换 Q 与第 0 层视频 K/V 前向投影后，三次更新的整体梯度相对误差为 **0.0040%、0.1006%、14.65%**。首步逐参数梯度及输出均通过；四卡记录均无算子回退，但第三步误差超过原实现，候选未启用。此次仍采用大文件身份和抽样校验。下一轮将对照固定的原生参数和 Adam 状态，区分单步算子误差与累积更新造成的放大。

独立的 checkpoint 问题已修复。全新 driver 曾遗漏恢复 Adam 动量，现按 checkpoint 中的分片构造加载状态，并检查 DCP 索引完整性。CPU 回归和四卡 FP32 小模型的三种拓扑均通过恢复与续跑。缺少动量且无法验证完整性的旧分布式 checkpoint 会被拒绝；完整模型和 BF16 的恢复仍待验收。

## 性能对比口径

四卡对比采用 **TP=4、PP=1 与 FSDP=4**，两边每个 rank、每个 microstep 使用相同 batch；不强求每次更新的全局样本数相同。双方使用 BF16，TP4 采用实验性的 VAE 分片候选。三次 microstep 分别处理 9、11、13 个样本，预热 2 次更新后统计 5 次更新：

| 方案                | 平均更新耗时 |      四卡整机吞吐 |
| ------------------- | -----------: | ----------------: |
| TP4（VAE 分片候选） |  约 14.46 秒 | 约 2.28 samples/s |
| FSDP4               |  约 34.21 秒 | 约 3.86 samples/s |

TP4 候选当前约为 FSDP4 吞吐的 **59%**，尚未通过完整模型正确性验收。两者每次更新处理的全局样本数分别为 33 和 132，因此应比较整机 samples/s，而非直接比较秒/步。本次包括输入准备、VAE、训练与优化器，不包括媒体解码和 checkpoint 写入；固定 fixture 在不同 rank 间复用，样本数按处理次数而非独立样本计，资源监控与历史 checkpoint 校验仍有限制，结果为暂定值。更早的 TP2/PP2 与 FSDP 单步数据因批次和累积设置不同，不能直接比较。

11 月 24 日按同样的 microstep batch 加入逐槽计时。TP4 完成 2 次预热和 5 次计时更新，FSDP4 在收到暂停指令前完成 2 次预热和 4 次计时更新。取双方共同的 4 次更新，每步以四卡中最慢 rank 的计时为准，TP4 为 14.57 秒、2.27 samples/s，FSDP4 为 34.34 秒、3.84 samples/s，吞吐比例仍约为 59%。这是中断前的诊断数据，正式对比仍以完整计时窗口为准。TP4 的数据准备在主机侧约占 7 秒/步，这段计时包含 GPU 工作和等待，需用端到端复测确认可节省的时间。

## 后续重点

2. 在相同 microstep batch 和明确的资源、计时口径下，继续优化输入准备、计算与通信，复测四卡整机吞吐，目标为打平 FSDP4。
3. 完成 576 槽容量、完整续训及生产编译配置验收；所有新候选先验证数值和资源，再报告性能。
